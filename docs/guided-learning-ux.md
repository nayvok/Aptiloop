# Guided Learning UX: спецификация рефакторинга

> **Historical snapshot — non-authoritative.** This file records an earlier **Implemented baseline** and is preserved for context only. Do not use it as the current UX specification. See the [current documentation index](README.md).

Дата: 2026-08-02
Статус: approved для реализации

## 1. Аудит текущего состояния

Продукт технически работает (Path, session resume, exercise, interview, settings, curriculum editor), но learner UI показывает внутреннее устройство harness-а вместо учебного маршрута.

Зафиксированные проблемы:

1. **Path дублирует день**: блок «Следующий шаг» раскрывает полный день — цель, результаты, темы, out-of-scope и все 12 unit-ов — и повторяет его же в общем списке недели.
2. **Нет трёх блоков дня**: пользователь видит плоский список unit-типов (Брифинг, Изучение, Воспроизведение, Диалог с Teacher, Квиз, Чтение кода, Упражнение, Review…), а не понятный маршрут «Изучение → Проверка → Практика».
3. **Нет оценки времени**: «0 из 12 · 168 минут» без контекста блока; нет «осталось в блоке», «осталось в дне».
4. **Session подчинён плану**: `DayPlan` с полным двухколоночным планом открыт по умолчанию над активным unit-ом; активная работа визуально не главная.
5. **Briefing — бюрократия**: обязательные чекбоксы «прочитал outcomes/out of scope/подготовил Zed/подтверждаю понимание» перед стартом.
6. **Источники — заголовки**: в Study источник — строка-ссылка без типа, главы, времени, указания «что найти»; при отсутствии источника нет честного пустого состояния.
7. **Терминология внутренняя**: Teacher Dialogue, Quiz, Exercise, Review, Evidence, interview-ready, версии r1–r4 на learner-экранах.
8. **Provider status шумный**: «3/3 подключено · Mock · Deterministic Mock · …» в шапке каждого экрана.
9. **Interview**: setup есть, но нет scoping «только изученные темы»; вопросы/отчёт рендерятся как сырой текст без Markdown/code formatting; нет явной дисклеймер-строки о границах оценки.
10. **Settings**: один длинный список провайдер/модель по ролям без группировки и профилей.
11. **Curriculum Editor**: список r1/r2/r3/r4 без выделения «текущей программы», история не свёрнута, нет сценария «Добавить следующую неделю».
12. **Пустые состояния** местами не объясняют следующее действие.

## 2. Принцип

На любом основном экране за 5 секунд видно один ответ: «Следующее действие: …». Приложение не объясняет устройство harness-а: revision, unit, evidence, provider/model остаются в developer tools и редакторе программы.

## 3. Группировка дня в три блока (presentation-level)

Модель unit-ов не меняется. Новый модуль `lib/learning-blocks.ts` группирует units:

| Блок                  | Units                                                   | Цвет                                                                                 |
| --------------------- | ------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| 1. Изучение           | briefing, study                                         | violet                                                                               |
| 2. Проверка понимания | recall, teacher-dialogue, quiz, code-reading, interview | amber (recall), cyan (teacher), blue (quiz), indigo (code-reading), pink (interview) |
| 3. Практика           | exercise, review, summary, checkpoint, spaced-review    | emerald (practice), coral (review), green (summary)                                  |

Интерфейс показывает «3 учебных блока · около 2 ч 48 мин», детальные units — только во вторичном плане (drawer/accordion).

## 4. Path (`/`)

### Верх: «Сегодня»

- название текущего дня: «День 1 · Значения, типы и объекты»;
- текущий блок: «Блок 1 из 3 · Изучение»;
- текущий шаг: «Значения и примитивы · около 18 минут»;
- оставшееся время дня;
- один CTA: «Начать обучение» / «Продолжить обучение»;
- без раскрытия всего curriculum.

### Середина: «Текущий день» — три блока

Для каждого блока: иконка + label + цвет activity, состояние (готово/сейчас/доступно/заблокировано), прогресс (шаг N из M), время, текущий/следующий шаг.

Полный список units — через «Посмотреть подробный план дня» (drawer/accordion/modal).

### Низ: «Путь недели»

Компактные карточки дней: номер, название, краткая цель, время, прогресс, статус (завершён/текущий/доступен/заблокирован). Без повторения деталей раскрытого дня.

## 5. Session (`/session`)

- sticky компактный header: «День 1 · …», «Изучение · Шаг 2 из 5», progress bar, «Осталось в блоке: …», кнопка «План дня»;
- активный unit — главный элемент по центру; план дня — в drawer (по умолчанию закрыт) или правой панели;
- после завершения блока — transition screen: «Блок „Изучение“ завершён», разобранные темы, следующий блок + время, CTA «Продолжить сейчас» / «Вернуться позже» (прогресс уже сохранён);
- «Продолжить позже» доступно из заголовка в любой момент.

## 6. Briefing

Компактные секции без обязательных чекбоксов:

- «Сегодня разберём» (темы);
- «После занятия сможешь» (outcomes);
- «Уровень: Для собеседования» + краткое пояснение;
- «Не углубляемся» (out-of-scope);
- «План» (три блока и время);
- «Источники».

Один CTA «Перейти к изучению»; вторичное действие «Пройти диагностику без изучения». Завершение — один подтверждающий клик (серверный completion criterion `acknowledgement` сохраняется).

## 7. Study sources

Для Study unit — карточки источников: название, тип (книга/документация/видео/статья/локальная заметка), глава/раздел (из `learningGoal`/`description`), страницы/таймкод (если указаны), время, основной/дополнительный, «Открыть материал», «Обрати внимание: …».

Если источников нет: «Для этого шага источник ещё не назначен.» + «Использовать свой источник» (открыть курсор на внешнем материале) и «Открыть редактор программы».

## 8. Learner-терминология

| Внутреннее       | Learner UI                |
| ---------------- | ------------------------- |
| interview-ready  | Для собеседования         |
| study            | Изучение                  |
| recall           | Воспроизведение по памяти |
| Teacher Dialogue | Разбор с преподавателем   |
| Quiz             | Короткая проверка         |
| Code Reading     | Чтение кода               |
| Exercise         | Практическое задание      |
| Read-only Review | Проверка решения          |
| Summary          | Итоги дня                 |
| Evidence         | Подтверждения навыка      |

Английские технические термины (Event Loop, Promise, closure, shallow/deep copy, type narrowing) сохраняются. Internal IDs, revision-номера и provider/model не показываются на learner-экранах.

## 9. Provider status

Компактно: «● AI готов» / «● Преподаватель готов»; по клику — popover: Teacher/Reviewer/Expert provider/model и состояние; полные lifecycle details — «Настройки → Инструменты разработчика». Ошибки провайдера показываются локально у действия, которое от него зависит.

## 10. Interview

### Setup

- темы; scope: «Только изученные» (default), «Текущая неделя», «Выбрать вручную», «Полная диагностика»;
- сложность; количество вопросов; длительность (оценка);
- provider/model — только в расширенных настройках.

«Только изученные» вычисляется клиентски из `/learning/path`: темы дней, где есть завершённые/начатые units.

### Во время

Вопрос N из M, тема, ожидаемое время, корректный Markdown и code blocks (react-markdown + remark-gfm), поле ответа, один CTA.

### Отчёт

Структура/полнота, слабые места, вопросы для повторения, карточки. Явная строка: «Оценена структура и полнота ответа. Техническая корректность не проверялась.»

## 11. Settings

- **Основные**: тема, exercise workspace, редактор (read-only info);
- **AI для обучения**: роли с понятными названиями (Преподаватель, Проверка решения, Интервьюер, Итоги и повторение, Эксперт) + профили «Экономный» / «Сбалансированный» / «Максимальная точность» (набор provider/model для ролей); ручной выбор — в «Расширенные настройки»;
- **Подключения**: OpenCode, Codex, health check, краткая диагностика;
- **Для разработчика**: endpoint, model list, process lifecycle, Agent Playground, provider events.

## 12. Curriculum Editor

- «Текущая программа»: Версия N, Опубликована, дата, недели/дни, «Создать новую редакцию»;
- «История версий»: свёрнутый список с деталями по раскрытию;
- сценарий «Добавить следующую неделю»: название/цель → темы → результаты → дни → ручное редактирование → preview → publish. AI генерирует только draft, никогда не публикует.

Versioning, immutable publish и ручной CRUD/reorder/clone сохраняются без изменений.

## 13. Визуальная система

Холодная нейтральная палитра сохраняется. Добавляются semantic activity-цвета: study violet, recall amber, teacher cyan, quiz blue, code-reading indigo, practice emerald, review coral, interview pink, summary green. Цвет не единственный индикатор: иконка + label + border + status text. WCAG AA, reduced motion, keyboard/focus, light/dark/system.

## 14. Empty/loading/error states

Каждое пустое состояние объясняет действие: «Сейчас нет активного занятия. Перейди к учебному пути и начни следующий доступный блок.», «Источник ещё не назначен», «AI недоступен», «Zed не найден», «Diff отсутствует», «Тесты не запускались», «Review устарел после изменения кода», «Нет карточек», «Интервью ещё не запускалось».

## 15. Acceptance criteria

1. Path не дублирует подробный текущий день.
2. День сгруппирован в 3 блока.
3. Подробные units вторичны (drawer).
4. На Path один главный CTA.
5. Briefing без обязательной бюрократии.
6. Study показывает источники или честное пустое состояние.
7. Активный unit — главный элемент Session.
8. План дня не вытесняет активную работу.
9. Transition screen после блока.
10. «Вернуться позже» сохраняет прогресс.
11. Learner-терминология без внутренних терминов.
12. Provider status компактный.
13. Полная диагностика — в developer tools.
14. Interview имеет setup со scoping «только изученные» по умолчанию.
15. Markdown/code рендерятся корректно; отчёт честный.
16. Settings разделены по назначению с профилями.
17. Curriculum Editor выделяет текущую версию и «Добавить следующую неделю».
18. Светлая/тёмная темы согласованы; нет горизонтального overflow на 1280/1440/1920/tablet.
19. Existing functionality (curriculum/session/exercise/interview) не сломана; fast tests, component tests, Playwright и production build проходят.
