# Collection toolkit

Цель упражнения — самостоятельно восстановить базовые преобразования коллекций и объяснить выбранные структуры данных. В `src/collection-toolkit.ts` находятся три TODO-заготовки. Не просите агента писать решение: сначала реализуйте их в Zed, затем запускайте тесты.

## Контракт

- `groupBy(items, getKey)` возвращает `Map`, сохраняет порядок появления групп и порядок элементов внутри каждой группы.
- `uniqueBy(items, getKey)` возвращает новый массив и оставляет первый элемент с каждым ключом.
- `countBy(items, getKey)` возвращает `Map` с количеством элементов для каждого ключа.

Ключ может быть любого типа, включая объект. Ни одна функция не должна менять входной массив. Пустой вход должен давать пустой результат.

## Ограничения

- Не использовать lodash или готовые аналоги.
- Не сортировать вход.
- Не применять `any` и type assertions для обхода TypeScript.
- Каждая операция должна выполняться за один проход по `items`.
- Не менять тесты ради прохождения проверки.

## Готово, когда

- Все тесты проходят.
- `npm run typecheck` завершается без ошибок.
- Вы можете объяснить, почему здесь выбран `Map`, как сохраняется порядок и какова временная сложность.

## Запуск

Сначала установите зависимости один раз из корня репозитория (`npm install`),
затем из этой папки:

```bash
npm test
npm run typecheck
```

Стартовые тесты намеренно красные: TODO-функции бросают исключение, пока вы их не реализуете.

После основной части добавьте два собственных теста: для ключа-объекта и для проверки отсутствия мутации входа.
